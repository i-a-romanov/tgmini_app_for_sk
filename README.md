# SK Fast Track — Telegram Mini App

Рабочий MVP: Telegram-авторизация, личный план, задания, материалы, дедлайны и необязательные напоминания. Подготовлен для бесплатного пилота на Render.

**[Пошаговый запуск: Render + BotFather](docs/DEPLOY_RENDER.md)**

## Что работает

- Проверка подписанных `initData`, сессии и настоящий профиль Telegram.
- Три маршрута: конкурс грантов (16 задач), выбор программы (6), знакомство (6).
- PostgreSQL: настройки, черновики ответов, выполненные задания, прогресс и личные даты.
- Авторские материалы по эссе, интервью, опыту и резюме; рабочий чек-лист без загрузки файлов.
- Личные дедлайны: создание, выполнение, удаление, экспорт `.ics` через временную ссылку.
- Нативные MainButton, BackButton, SettingsButton, темы и haptics; без нарисованной рамки телефона.
- Бот `/start`, `/help`, `/stop`, `/delete`; настройка webhook и меню при старте.
- Добровольные ежедневные напоминания с timezone и защитой от повторов.
- Правила хранения и удаление профиля вместе с данными и сессиями.

Это рабочая версия, а не прежнее демо. Она **ещё не развёрнута в вашем Render и не проверена с вашим ботом на телефоне**: токен и аккаунт добавляете вы. ИИ-разбор файлов, платежи и отправка заявки в Сколково в MVP не входят. Официальные сроки не выдумываются: пользователь добавляет проверенные им личные даты.

## Локально

Node.js 24:

```sh
npm ci
npm run dev
```

Откройте `http://127.0.0.1:3000`. Локально используется тестовый профиль и PostgreSQL-совместимая PGlite-база в `.localdb/`. Бот и отправка сообщений отключены. Этот режим запрещён на Render и в production.

## Render

Подключите репозиторий через **New → Blueprint**, выберите корневой `render.yaml` и задайте `BOT_TOKEN`. Blueprint создаст бесплатные Web Service и PostgreSQL, свяжет базу и сгенерирует секрет webhook. URL берётся из `RENDER_EXTERNAL_URL`.

- Build Command: `npm ci --omit=dev`
- Start Command: `npm start`
- Health Check: `/healthz`

Бесплатный сервис засыпает; напоминания не гарантируются. Render Postgres Free истекает через 30 дней. Подробности — в [инструкции](docs/DEPLOY_RENDER.md).

## Проверки

```sh
npm test
npx playwright install chromium
npm run test:e2e
node scripts/check-render.mjs
```

Серверные тесты используют PGlite. Browser-тест поднимает изолированный сервер на `127.0.0.1:4197`, делает реальные HTTP-запросы с подписанной тестовой авторизацией; заменён только Telegram host bridge. Реальные сообщения не отправляются. Можно задать `CHROME_PATH` для установленного Chromium-браузера.

[Результаты и границы проверки](docs/verification.md).

## Структура

```text
public/             рабочий интерфейс: HTML, CSS, JavaScript
server/             Fastify, авторизация, PostgreSQL, контент, бот
server/schema.sql   начальная идемпотентная миграция
tests/              серверные и SQL-тесты
scripts/            browser-тест, проверка Render, настройка бота
render.yaml         бесплатный пилот
.env.example        описание переменных без секретов
docs/               инструкции и проверка
prototype/          первоначальный дизайн-прототип
output/design/      макеты и CJM этапа проектирования
```

Фронтенд сохранён на обычном JavaScript, чтобы использовать утверждённый дизайн без лишней сборки. На Render раздаётся только `public/`; файлы проекта не доступны через веб-сервер. Секреты остаются на сервере.

Макеты можно отдельно открыть через `output/design/index.html`. Старый дизайн-ZIP не предназначен для развёртывания. Для загрузки актуального релиза вручную используйте `output/sk-fast-track-render.zip`.
