# Запуск в Telegram через Render

Рабочий MVP · 22 ноября 2026 · бесплатный пилот.

## 1. Создайте бота

В официальном [@BotFather](https://t.me/BotFather) отправьте `/newbot`, задайте название и username с окончанием `bot`. Можно использовать существующего бота.

Скопируйте токен. **Вставляйте его только в Render Environment: не в GitHub, HTML или переписку.** Другие программы не должны одновременно менять webhook этого бота или читать обновления через long polling.

## 2. Отправьте файлы в GitHub

Remote проекта указывает на `i-a-romanov/tgmini_app_for_sk`. Из папки проекта:

```sh
git status
git add .
git commit -m "Build Telegram Mini App for Render pilot"
git push
```

Проверьте изменения перед коммитом. `.env`, `node_modules`, `.localdb` и тестовые скриншоты исключены через `.gitignore`. `.env.example` не содержит секретов.

Для загрузки вручную можно распаковать `output/sk-fast-track-render.zip` и добавить его содержимое в репозиторий. Сам ZIP вместо файлов Render не запустит.

## 3. Создайте Blueprint

1. В [Render Dashboard](https://dashboard.render.com/) выберите **New → Blueprint**.
2. Подключите GitHub и репозиторий, выберите ветку с изменениями.
3. Файл конфигурации — **`render.yaml` в корне**.
4. Убедитесь, что создаются Web Service `sk-fast-track` и PostgreSQL `sk-fast-track-db`, оба на **Free**, в одном регионе.
5. В поле **`BOT_TOKEN`** вставьте токен из BotFather.
6. Подтвердите создание и дождитесь успешного деплоя.

Blueprint сам свяжет `DATABASE_URL`, сгенерирует `WEBHOOK_SECRET` и включит настройку бота. URL определяется через `RENDER_EXTERNAL_URL`. Начальная схема базы создаётся приложением до запуска сервера; отдельная ручная миграция не требуется. Конфигурация следует [официальной спецификации Blueprint](https://render.com/docs/blueprint-spec).

Если в аккаунте уже есть Free PostgreSQL, Render может не разрешить вторую. Можно вручную использовать существующую совместимую базу и её Internal Database URL вместо создания новой. Не удаляйте действующую базу ради пилота.

## 4. Проверьте сервер

В Render откройте **Web Service** и скопируйте адрес вида `https://…onrender.com`.

- По `/healthz` должен возвращаться `{"ok":true}` — сервер и база доступны.
- В логах настройки бота должна появиться строка **`Telegram webhook and menu configured`**.
- В обычном браузере приложение попросит открыть его в Telegram. Это правильно: публичного тестового входа нет.
- Если есть `Telegram setup failed`, исправьте `BOT_TOKEN` и перезапустите сервис или выполните **Manual Deploy → Deploy latest commit**.

Build Command: `npm ci --omit=dev`. Start Command: `npm start`. Node.js: 24. Никогда не устанавливайте `DEV_AUTH=true` на Render: приложение специально откажется запускаться.

## 5. Включите Main Mini App

Кнопка **«Мой план»** в меню чата создаётся автоматически. Для прямой ссылки и кнопки в профиле настройте Main Mini App:

1. В BotFather: `/mybots` → ваш бот → **Bot Settings → Configure Mini App → Enable Mini App**.
2. Вставьте HTTPS-адрес Web Service **без `/prototype`, `/public` или `/output/design`**.
3. Добавьте описание и подходящую иконку. Файлы `public/icon.svg` и `public/icon.png` входят в релиз.
4. Если названия пунктов в клиенте отличаются, найдите настройку Main Mini App. URL её запуска и кнопки меню должен быть одинаковым.

Приложение использует [официальный Telegram WebApp API](https://core.telegram.org/bots/webapps), а сервер проверяет подпись и срок действия исходных данных входа.

## 6. Откройте на телефоне

1. Отправьте своему боту `/start`.
2. Нажмите **«Открыть мой план»** в сообщении или **«Мой план»** в меню.
3. Выберите цель, темп и часовой пояс. Напоминания необязательны.
4. Активируйте план, выполните задачу, закройте и снова откройте приложение — прогресс должен сохраниться.

Если разрешение на напоминания не подтвердилось, отправьте боту `/start` и включите их снова. `/stop` выключает сообщения. После настройки Main Mini App доступна ссылка `https://t.me/USERNAME_БОТА?startapp=shared`; приложение формирует её по настоящему username. При переименовании бота перезапустите сервис.

## Проверка после деплоя

- [ ] Имя приходит из Telegram, у нового пользователя нулевой прогресс.
- [ ] Работают светлая/тёмная темы, MainButton и BackButton на телефоне.
- [ ] Черновик восстанавливается после повторного открытия.
- [ ] Повторное завершение не увеличивает счётчик дважды.
- [ ] Личные даты видны только своему пользователю.
- [ ] `.ics` загружается и импортируется в календарь. Старые Telegram открывают файл через браузер.
- [ ] Материалы открываются, смена цели меняет план.
- [ ] `/stop` отключает сообщения; после обновления это видно в профиле.
- [ ] Удаление профиля отзывает сессии и удаляет рабочие данные.
- [ ] В Environment заданы ваши `OPERATOR_NAME` и, желательно, `SUPPORT_URL`.

Эти проверки с вашим ботом ещё предстоят: код проверен локально, но доступа к вашему Render и токену не было.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `NODE_ENV=production` | Уже в Blueprint |
| `BOT_TOKEN` | Вы вводите секрет BotFather |
| `DATABASE_URL` | Blueprint связывает с внутренним URL PostgreSQL |
| `WEBHOOK_SECRET` | Генерируется Blueprint; сервер преобразует в допустимый Telegram секрет |
| `AUTO_CONFIGURE_BOT=true` | Настройка webhook, меню и команд при запуске |
| `ENABLE_REMINDERS=true` | Планировщик; согласие пользователя всё равно требуется |
| `PILOT_MODE=true` | Показывает ограничение бесплатного сервиса |
| `APP_URL` | Необязательно: свой HTTPS-домен без пути; после изменения нужен перезапуск |
| `OPERATOR_NAME` | Фактическое название вашей команды |
| `SUPPORT_URL` | Необязательная HTTPS-ссылка на поддержку |
| `DATABASE_SSL=true` | Для внешней базы с проверяемым TLS; для внутреннего Render URL обычно не требуется |
| `PORT` | Render задаёт сам |

При своём домене URL в Telegram и `APP_URL` должны совпадать. Сервер проверяет источник изменяющих запросов.

## Ограничения Free

Бесплатный Web Service засыпает после 15 минут без входящих запросов; первый запрос после простоя может запускаться около минуты. PostgreSQL Free действует **30 дней**, не имеет резервных копий и допускает только одну бесплатную базу в workspace. После истечения срока база недоступна; позднее Render удаляет её. [Ограничения Render Free](https://render.com/docs/free).

Приложение не удерживает сервер искусственными пингами. Планировщик проверяет время раз в минуту только в живом процессе: не больше одного напоминания за локальный день, в течение 30 минут после выбранного времени. После долгого сна пропущенное сообщение не досылается. После неоднозначного сетевого сбоя повторной отправки в тот же день нет, чтобы не создавать дубликаты. Важные даты дополнительно экспортируйте в календарь.

Прогресс хранится в PostgreSQL, а не в файловой системе Web Service. Перезапуск приложения его не удаляет; истечение или удаление базы лишает доступа к данным. До окончания 30 дней выберите дальнейшее хранилище или экспортируйте базу. Для стабильных уведомлений нужны постоянный сервер и долговременная база.

## Если не работает

| Симптом | Что проверить |
|---|---|
| Ошибка сборки | Файлы проекта и lock-файл в корне; `npm ci --omit=dev`, Node 24 |
| Ошибка `DATABASE_URL` | Сервис связан с базой; при ручном создании указан Internal Database URL |
| База недоступна | Она работает, не истекла; сервис и база в одном регионе |
| Ошибка `APP_URL` | HTTPS-origin без пути; обычно хватает автоматического Render URL |
| Ошибка `WEBHOOK_SECRET` | Случайная строка от 32 символов или генерация через Blueprint |
| `Telegram setup failed` | Правильный токен без пробелов; затем перезапуск |
| «Откройте в Telegram» в браузере | Ожидаемо: запускайте через бота |
| «Ссылка устарела» | Полностью закройте Mini App и откройте снова |
| Настройки не сохраняются | Связь, правильный домен; при конфликте с другим окном обновите профиль |
| Нет напоминаний | Разрешение, активный план, timezone, время, состояние сервера, `/stop` |
| Не работает прямая ссылка | Main Mini App в BotFather, не только кнопка меню |
| Нет данных через месяц | Срок бесплатной базы |

## Границы релиза

Реализованы авторизация, план, упражнения и материалы, черновики, личные даты и календарь, настройки, бот, ежедневные напоминания и удаление данных. Вход в одном аккаунте Telegram возвращает тот же профиль.

Загрузка/ИИ-разбор резюме, платежи, получение официальных сроков из системы Сколково и отправка заявки не входят в этот MVP. Резюме проверяется работающим чек-листом, материалы — самостоятельные рекомендации, не официальные критерии.
